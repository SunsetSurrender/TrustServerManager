# Password vietate. Lista LOCALE, letta da app/auth/passwords.py.
#
# In rete chiusa non esiste un servizio da interrogare: nessuna API di «password
# compromesse», nessun k-anonymity range query, nessun aggiornamento automatico.
# Il controllo deve funzionare senza uscire dalla macchina, quindi la lista è un
# file che viaggia con l'immagine.
#
# ── Come si confronta ────────────────────────────────────────────────────────
# UGUAGLIANZA sull'intera password, dopo NFC e casefold. NON sottostringa.
# Cercare queste voci dentro la password sembrerebbe più severo e sarebbe invece
# controproducente: rifiuterebbe «il gatto dorme sul tetto di casa» perché
# contiene «casa», cioè colpirebbe le passphrase lunghe che la politica vuole
# incoraggiare, lasciando passare `Estate2026!` perché non contiene nessuna voce.
#
# ── Perché quasi tutte le voci sono lunghe ───────────────────────────────────
# Il minimo è 15 code point. Le classiche — `password`, `123456`, `qwerty` — sono
# già rifiutate dalla LUNGHEZZA, prima di arrivare qui. Restano comunque in fondo
# per difesa in profondità, ma non sono il lavoro di questo file.
#
# Il lavoro vero è l'altra cosa: che cosa scrive una persona a cui il sistema ha
# appena chiesto quindici caratteri. Le risposte sono poche e ricorrenti — la
# password corta scritta due volte, una camminata più lunga sulla tastiera, una
# frase fatta, il nome del programma. Sono quelle le voci che contano, e sono
# quelle che una lista pensata per il minimo di otto caratteri non contiene.
#
# ── Manutenzione ─────────────────────────────────────────────────────────────
# Una riga per voce. `#` inizia un commento. Righe vuote ignorate.
# Aggiungere una voce non invalida nessun hash esistente: la lista si applica
# quando una password si IMPOSTA, non quando si verifica (§8.41). Chi ha già una
# password che finisce nella lista non viene bloccato fuori, e non deve esserlo:
# scoprire di essere bloccati durante un accesso non lascia nessuna via d'uscita.
